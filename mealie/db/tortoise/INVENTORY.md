# Implicit behaviour of the SQLAlchemy models

Generated by dev/scripts/generate_tortoise_models.py (stage S2 of REWRITE_PLAN.md). None of this is
visible in the database schema; it lives in SQLAlchemy relationship settings, type annotations,
association proxies and the auto_init decorator.

| Behaviour | Where it lives in the SQLAlchemy code | Count |
|---|---|---|
| Children deleted with the parent | `relationship(cascade="...delete...")` | 65 relations on 15 models |
| Child foreign key cleared when the parent is deleted | default relationship behaviour | 7 relations on 6 models |
| Columns allowed in query filters | `FilterableColumn[...]` annotations | 338 columns |
| Association proxies | `association_proxy(...)` | 25 attributes on 14 models |
| Proxies that are `group_id` / `household_id` (query scoping) | same | 22 |
| One-to-many relations written from nested dicts | `@auto_init()` | 40 relations on 11 models |
| One-to-one relations (`uselist=False`) | relationship settings | 6 |
| Composite primary keys (Tortoise has none) | table definitions | 7 tables |
| Unbounded indexed strings limited to 255 characters | table definitions | 35 columns |

Lazy loading: SQLAlchemy loads a relation when a schema reads it; Tortoise raises unless it was
fetched first, so the repositories fetch the relations each schema reads.
